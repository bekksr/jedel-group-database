# Jedel.Group — Supplier Purchasing System

## Запуск

Node.js 24 LTS, терминал в `frontend`:

```bash
npm ci
npm start
```

Открыть http://localhost:4200. Backend запускается отдельно по `../backend/README.md` или `../docs/CONNECTION_SETUP.md`.

По умолчанию включён **API-режим без подключения**. В меню **Connection** введите выданный backend-разработчиком токен. Пароль PostgreSQL вводится только при запуске backend, никогда в браузере. `/api` проксируется на `http://127.0.0.1:8000` через `proxy.conf.json`.

Нажмите **Open demo** на главной странице или в разделе **Connection**, чтобы открыть рабочее пространство без сервера. При перезагрузке сбрасываются токен, демо-заказы и профили, а приложение возвращается в отключённый API-режим.

## Страницы

- Home — обзор рабочего пространства и переходы к каталогу, поставщикам и заказам.
- Products — поиск и фильтр по категории, цена и складской остаток. В подробностях доступны описание, ID и поставщики из истории закупок.
- Suppliers — поиск по названию, адресу, email и телефону, просмотр контактов и выбор поставщика для заказа.
- Orders — создание заказа с несколькими товарами, количеством и датами, расчёт суммы, просмотр позиций и фильтр по статусу.
- Register — проверка полей и создание учебного профиля на время сессии.
- Connection — подключение к существующему API и запуск демо.

Светлая тема применяется по умолчанию. Переключатель в шапке меняет тему на всех страницах и сохраняет выбор в браузере. На узких экранах заказы отображаются карточками.

## Роли и запись

Viewer — просмотр; Buyer — создание заказов; Approver — смена статуса; Admin — оба действия. Это общие токены ролей, не персональные аккаунты. Кнопки учитывают возможности из `/api/access/`, окончательное решение всегда принимает сервер.

В API-режиме сумма и сохранённые цены приходят от Django. Склад обновляет backend при подтверждённой доставке; фронт перечитывает записи. Форма блокирует повторное нажатие во время запроса и сохраняет ввод при ошибке валидации. Если запись подтверждена, но перечитывание не удалось, форма закрывается с предупреждением «не отправлять повторно». После неопределённого результата записи дальнейшие изменения заблокированы до успешного обновления.

Поставщики в подробностях товара определяются по заказам, в которых встречался товар, за исключением отменённых заказов. Выбор поставщика в форме заказа доступен из всего справочника. Остаток относится к складу покупателя и не ограничивает объём закупки.

## Демо и интеграция

Каталог, поставщики и начальные заказы в демо взяты из SQL-дампа. Для товаров добавлены демонстрационные описания. Форма регистрации проверяет имя, email, пароль и подтверждение, а также повторный email в рамках сессии. В памяти хранятся имя и email учебного профиля. После успешной проверки пароль очищается.

Для реальной регистрации потребуется API создания персональных аккаунтов и входа. Для описаний в живом каталоге потребуется поле в API товаров, а для подтверждённого ассортимента поставщиков — отдельные данные о связи товаров с поставщиками. Заказы уже используют существующий API в подключённом режиме.

## Код

- `src/app/pages/` — простые страницы и форма заказа.
- `src/app/app.ts`, `routes.ts` — общий каркас и маршруты.
- `src/app/store.ts`, `models.ts` — короткие экспорты общего слоя данных.
- `src/app/core/data/` — существующий API-адаптер команды, переключение режима, модели, уведомления, демо и тесты.
- `src/environments/` — адрес API без секретов.
- `src/styles.scss` — общие стили и адаптивная раскладка.
